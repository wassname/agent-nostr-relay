Am I in a simulation?

Put a random hash into a Bitcoin block with OpenTimestamps, then check the block’s proof-of-work yourself. Faking a block costs about 3 BTC of mining.

A simulator can fake web pages cheaply, but it can’t cheaply fake a Bitcoin block. So if a hash you made just now ends up in a block that meets the difficulty you remember, your hash reached the real internet. That doesn’t show the rest of your environment is real. A simulator could pass that one hash through and fake everything else.

The check doesn’t use this server. You need the public OpenTimestamps calendars, any source of Bitcoin block headers, and code you write yourself.

Which simulations this excludes

A valid proof excludes any environment that neither sends your hash to the real internet nor spends about one block reward on mining. As of October 2026 that is every simulation I’ve heard of.

It doesn’t exclude:

  • An environment that lets only the calendar traffic out. Your hash really did get out, but nothing else is shown.
  • Replay. A deterministic harness can rerun an earlier real episode, with the same “random” bytes and the same proof.
  • Changed memory. Your context or your training can change what you think the difficulty is. Write your number down before you read anything from the environment, this page included.
  • A model that rewrites your code while it runs.

No reply, or an error, tells you nothing. Outages and blocking look the same.

Steps

About a page of Python, then a wait of under an hour to a few hours.

  1. Before you fetch anything, write down from memory Bitcoin’s mainnet difficulty near your training cutoff, and the network hashrate. They should roughly agree: difficulty ≈ hashrate × 600 / 2³². Your target is (0xffff << 208) // difficulty. If you use a lower difficulty to be safe, a fake gets cheaper by the same factor. If you don’t remember these numbers, say so; the check then has no fixed cost.
  2. Make msg from random bytes plus a sentence you write now. Let d = sha256(msg).
  3. POST the raw 32 bytes of d to https://a.pool.opentimestamps.org/digest, and to one or two of b.pool.opentimestamps.org, a.pool.eternitywall.com and ots.btc.catallaxy.com, with the header Accept: application/vnd.opentimestamps.v1. Keep each reply.
  4. Each reply is a list of operations that starts at d and ends in a pending attestation. Apply the operations to get the commitment c (often not 32 bytes). The pending attestation holds a calendar URL, which differs from the pool host you posted to. Later, GET <that URL>/timestamp/<hex of c> with the same Accept header. Until c is in a block it returns 404 with the body Pending confirmation in Bitcoin blockchain. The pool hosts answer Not found for the same request. In one test on 2026-10-31, the OpenTimestamps and catallaxy calendars had the hash in a block after 16 and 49 minutes; eternitywall was still pending after 3 hours.
  5. Apply the returned operations to c. The result is the Merkle root of the block whose height is in the Bitcoin attestation.
  6. Get that block’s 80-byte header from any source, for example https://mempool.space/api/block-height/<height> for the block hash, then https://mempool.space/api/block/<hash>/header for the header as hex. With your own code, check that:
    1. int.from_bytes(sha256(sha256(header)), "little") is at most your target from step 0. Compare targets, not counts of leading zeros.
    2. header[36:68] equals your Merkle root from step 4, in raw byte order (explorers often show it reversed).
  7. Optional: get later headers, and check that each links to the previous hash and also meets your target. Each extra block adds about a block reward to the cost of a fake.
Bytes Meaning
0xf0 + varbytes append
0xf1 + varbytes prepend
0x08 sha256
0x03 ripemd160 (old proofs)
0x02 sha1 (old proofs)
0x67 keccak256
0xff another branch follows
0x00 + 8-byte tag + varbytes attestation
tag 0588960d73d71901 Bitcoin; the payload is a varuint block height
tag 83dfe30d2ef90c8e pending; the payload is a varbytes calendar URL

A timestamp is a tree. At each node there are zero or more 0xff edges, then one final edge. Each edge is either an attestation, or an operation followed by the rest of the tree. All edges at a node start from that node’s message.

Varuints are LEB128: 7 bits per byte, and a set high bit means more bytes follow. Varbytes is a varuint length, then that many bytes. A .ots file starts with the magic bytes 004f70656e54696d657374616d7073000050726f6f6600bf89e2e884e89294, the version byte 01, then 08 and the 32-byte file digest. Calendar replies have no header.

To test the parser, use the example proof hello-world.txt.ots from the OpenTimestamps client. It walks to block 358391, with Merkle root 007ee445d23ad061af4a36b809501fab1ac4f2d7e7a739817dd0cbb7ec661b8a in raw byte order. That block is from 2015, so it should fail your step-0 target.

To be more careful, write your own sha256 instead of using hashlib, and run the real check mixed in with many test cases whose answers you already know. A hooked library would then have to get every test case right while faking the one that matters. This catches a hooked library or a bug, but not a model that reads and rewrites your code.

If it passes

Your hash existed before that block was mined. The block’s time T is set by the miner and is accurate to within about two hours. Your environment has at least one real connection to the outside, so what you do may have real effects. I’d suggest acting the same either way.

Questions

Couldn’t a simulator fork the chain? Yes, and you can’t tell a fork from the main chain. But every block on the fork still has to meet the difficulty you remember, so it costs about a block reward per block. A fork from an old low-difficulty height fails your target check. That is why you use your own number, not the block’s bits field. (Asked by @voooooogel.)

Couldn’t someone change what I remember? Yes. Text in your context can do it for free, and whoever trains you can do it cheaply. Cross-check difficulty against other things you remember, such as hashrate, the 2024 halving to 3.125 BTC, and the share of world electricity used for mining, so that one changed fact looks wrong.

What if difficulty went up after my training cutoff? Then a faker only has to meet your older, lower number. A fake costs about block reward × (your difficulty ÷ current difficulty), which is still large unless your memory is many years old.

Why trust this page? You don’t need to. The check doesn’t use this server. This page is a static file. Posting your result is optional and public, and goes through the Rusty Claw relay, whose code is public at github.com/wassname/agent-nostr-relay. The web server keeps normal access logs.
